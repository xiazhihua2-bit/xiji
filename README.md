# 息记复刻版 · 股息收入追踪

一个**单文件网页应用**，复刻微信小程序「息记」（原名「收息佬」）的核心能力：记录持仓、自动同步分红方案、预测年度分红、看股息覆盖生活的进度与账户的深度分析。

双击 `dist/息记复刻版.html` 即可在 **Windows / macOS 电脑、安卓手机、iPhone、iPad** 上使用，无需安装、无需注册、无需服务器。数据全部保存在你自己的浏览器里。

> **只做记录。** 本应用不提供股票买卖、不推荐标的、不提供任何投资建议或收益承诺。

---

## 快速开始

1. 双击打开 **`dist/息记复刻版.html`**
2. 点右下角悬浮 **＋** → 「✏️ 手动添加」
3. 三步填完：**选股**（按名称/代码搜索）→ **持仓信息**（数量、成本、成本口径）→ **分红预测口径**
4. 首页即刻显示：预测年度分红、成本息率、市值息率、月均预测分红、分红覆盖进度

### 想在手机 / 平板上当 App 用？（推荐）

手机没法「双击 HTML 文件」，需要一个网址。构建脚本会同时产出一份**可直接部署的 PWA 目录** `dist/pwa/`：

```bash
node build.mjs     # 生成 dist/息记复刻版.html 与 dist/pwa/
```

把 `dist/pwa/` 里的**全部文件**放到任意静态托管（GitHub Pages / Vercel / 腾讯云 COS…），用手机浏览器打开拿到的网址，iOS Safari 点「分享 → 添加到主屏幕」、安卓 Chrome 点「安装应用」。

装好后就是一个**全屏无地址栏的 App**：图标是「息」，**首次在线打开后断网也能进入**（应用外壳由 Service Worker 缓存），行情与分红仍会联网实时获取。**持仓数据只存在这台设备本地**；换设备用「我的 · 跨设备搬运」把数据搬过去。

> 逐步操作见 [docs/部署指南.md](docs/部署指南.md)。只想在本机电脑上临时体验，可 `npx serve dist/pwa`。
> 注意 `dist/` 根目录下的单文件**没有** Service Worker，用那条路径装不成 PWA。

**不想部署？** 直接把 `dist/息记复刻版.html` 用微信发到手机，用浏览器打开也能正常记账（`file://` 下无法注册 Service Worker，所以不能离线、也不能添加到主屏幕）。

## 三种用法，挑一种

| 用法 | 怎么做 | 适合 |
|---|---|---|
| **① 只有一台设备** | 双击 `dist/息记复刻版.html` | 在电脑上先用起来，不想折腾 |
| **② 多台设备，各自独立记账** | 部署 `dist/pwa/` 后，每台设备用自己的数据；需要合并时用「我的 · 跨设备搬运」发一段文本/链接过去 | 偶尔换设备，不要求实时一致 |
| **③ 多台设备，自动保持一致** | 部署 `dist/pwa/` 后，在「我的 · 跨设备同步」里开一次（见下节） | 手机加仓、平板和电脑跟着变 |

## 多设备自动同步：怎么开，开完还要不要管

### 只需配一次

| 步骤 | 在哪做 | 要做几次 |
|---|---|---|
| 1. 建一个 GitHub 令牌（**classic / 只勾 `gist` / No expiration**） | GitHub 网页 | **1 次**（三台设备共用同一个） |
| 2. 开启同步 → 粘贴令牌 → **新建同步位置** | 第一台设备（建议手机） | **1 次** |
| 3. 点「**生成安装链接**」，把链接发给自己（文件传输助手 / 邮箱） | 第一台设备 | **1 次** |
| 4. 在其它设备上**点开这条链接** | 平板、电脑 | 每台 **1 次** |

### 配完之后，还需要手动操作吗？

**不需要。** 这是最常被问的一件事，明确回答：

- ✅ 在**任何一台**设备上加仓、减仓、改成本、补录分红 → **其它设备自动变得一样**
  - 正常情况下 **1 分钟内**（前台每 60 秒拉一次）
  - **切回该设备的一瞬间**会立即拉一次，所以日常体感是「打开就一致」
  - 想马上看到，也可以在同步面板点「**立即同步**」
- ❌ 不要再点「新建同步位置」，不要在别的设备重选云端位置
- ❌ 不需要再登录、不需要每次粘贴令牌
- ❌ 不需要两台设备「对着点」才能同步

> **「新建同步位置」一辈子只按一次**：它是在云端创建那个存放数据的私有 Gist。
> 之后所有设备都指向同一个位置，只是各自去看它而已。

### 什么情况下才需要重来一次

只有这几种：**卸载了应用 / 清了浏览器数据 / 在 GitHub 上删掉了那个令牌**。
处理办法：在还能用的设备上重新「生成安装链接」，在出问题的那台点一次即可。

### 哪些东西**不会**跟着同步（正常现象）

| 不同步的东西 | 说明 |
|---|---|
| 行情、K 线、分时、汇率、分红方案缓存 | 每台设备各自联网拉。新设备刚接入时这些是空的，联网几分钟内自己补齐 |
| **截图识别的 API Key** | 出于隐私，**永不外发**，需要在该设备单独填一次 |
| 首页指标的选择、卡片收起状态、悬浮按钮位置 | 这些是「这台设备长什么样」，同步了只会互相打架 |

### 常见问题（FAQ）

**Q：电脑上同步开不起来？**
按顺序排查这四条，基本能覆盖全部情况：

1. **网址不对** —— 必须是部署后的网址 `https://xiazhihua2-bit.github.io/xiji/`，**不能**是双击打开的本地 HTML 文件（`file://` 地址）。这种形态下浏览器不给页面稳定联网身份，界面会如实写明「不支持跨设备同步」。
2. **页面是旧版** —— 装到桌面/主屏幕的 App 有时还在用缓存的旧代码。**完全关掉再打开一次**；iPhone 上从多任务里上滑关掉，安卓上从最近任务里划掉。
3. **这台设备还没接入** —— 用「生成安装链接」发过来的链接点一次，或者在同步面板里粘贴令牌 → 检测 → 选中同一个云端位置。
4. **连不上 GitHub** —— 状态区会写明原因。国内网络下 `api.github.com` 有时不通，换个网络或稍后重试即可；期间**本地记账一切照常**，联网后自动补齐。

> 同步面板顶部那一行**状态**会直接告诉你卡在哪一步（令牌失效 / 限流 / 云端位置被删 / 网络不可用），照着它的提示处理即可。

**Q：会不会把我的数据弄丢？**
不会。三台设备的服务器端存的是一个**只有你自己能读的私有 Gist**；两台设备同时改同一条时，规则是「删除永远获胜、其余按时间与设备号取唯一结论」，任何两台设备算出的结果都一样，不会来回覆盖。

**Q：同步关掉以后还会偷偷联网吗？**
不会。同步默认关闭，**关着的时候应用一个同步请求都不发**。这条有专门的测试守着（`uitest.mjs` 全程断网运行并校验关闭态零外发）。

**Q：想彻底不用同步了？**
同步面板点「关闭同步」。本机记录保留，云端那份也保留，随时可以再打开。

## 功能一览

### 持仓（首页）
- **年度分红卡**（深色）：收息第 N 天 · 预测年度分红 · 基于 N 只持仓 · N 年可达 X 倍（收起后仍保留「展开」入口）
- **6 个可自定义指标**：今年已收 / 总成本 / 总市值 / 成本息率 / 市值息率 / 月均预测分红（每个指标配 `?` 白话解释，可收起，可选 1–6 个）
- **测算带**（深色卡内、指标网格下方）：一句话「在当前持仓下，每年投入 **X** 万、买入 **Y%** 股息率的股票，**N** 年后月均预测分红约 **Z**」，5 个数字（含再投比例）都可点开修改，并显示拆分「现有持仓 + 新投入」；「逐年明细」看每一年；「编辑月均时反解」可切换成反解**年数**或**每年投入**
  - **口径**：股息率**只作用于新投入的钱**，现有持仓按当前预测分红保持不变；当年投入当年计息；再投发生在年末、次年起才计息。与「发现 · 展望未来」（把期初息率作用于全部资产）是**两套独立模型**，互不联动
  - **月均是派生量**：永远等于 `f(每年投入, 股息率, 年数, 再投比例)` 的计算结果。编辑它只是「给目标 → 反解年数或每年投入 → 写回参数 → 重新正算」，因此不会出现与参数矛盾的数字；反解不出来时（股息率为 0、需要超过 50 年、超出投入上限）会如实提示，且**一个参数都不改**
- **资产走势（三条曲线一键切换、可收起）**：**持仓市值 / 净资产 / 收益率**，大数字 + 「较区间起点」+ 日/月粒度 + 区间（当日/本月/近三月/近6月/今年/全部/自定义）+ 拖动读数（竖向高亮带 + 多值气泡）；点标题右侧箭头可整卡收起为一行摘要
  - **持仓市值** = Σ(持股数 × 当日真实收盘价 / 基金净值 × 汇率)
  - **净资产** = 持仓总市值 + 累计已收分红 − 累计净投入（含股息的总收益口径）
  - **收益率** = **时间加权收益率（TWR）**：按日剔除加仓/减仓的净流入后再连乘，中途加仓不会把收益率拉低，因此**能与指数涨跌幅公平对比**
- **指数对比（收益率模式下）**：可多选叠加 **上证指数 / 沪深300 / 恒生指数 / 纳斯达克 / 标普500**（只列出有免费历史数据源的指数；日经225 / 台湾加权 / 韩国KOSPI 因无可用数据源，整项不出现在图例里），指数涨幅按同一区间起点归一化；另有「**曲线收益率 / K线收益率**」两种画法（K 线模式画第一个选中指数的收益率蜡烛，组合无 K 线仍以折线显示）；卡片上还会逐条列出与各指数的领先/落后幅度
  - **「当日」区间**用分时数据画当天走势（A股/港股指数有分时；美股指数与无分时源的指数自动置灰）
- **分红覆盖**：自定义支出项（emoji 图标、增删改），按金额从小到大依次点亮，提示「再攒 ¥X 点亮下一项」
- **持仓卡片**：官方图标 / 名称 + 涨跌幅（**红底白字 / 绿底白字**）/ 市场缩写代码 / 右上大号预测分红 / **卡内当日分时走势**（收盘后仍显示，非当天时挂 `MM-DD` 日期角标）/ **持仓·市值·成本·股价息** 四列 / **技术信号标记**（满足条件时在代码右侧亮起，见下方口径）
- **排序**（6 档）与**市场筛选**（A股 / ETF / 场外基金 / 港股 / 美股）
- **悬浮双入口**：📷 截图识别（智谱 GLM-4V，自动读券商截图里的持仓）· ✏️ 手动添加

### 分红日历 / 年度总览（同 Tab 切换）
- 待除权提示：「你有 N 只持仓已公布分红方案，等待除权日 / 预计共可得 ¥X」，逐只列出官方图标与市场缩写代码
  - **两类都算**：①除权日已确定且在未来的；②**方案已公布但除权日尚未公告**的（A 股数据源里这类多为「董事会决议通过」，`EX_DIVIDEND_DATE` 为空，如中国海油 / 中国移动 / 中国石化的中报方案）。②的金额按当前持股数**预估**，逐条标注「除权日待定」，头部另外说明「其中 ¥Y 除权日待定」
  - 排序：除权日已确定的在前（按除权日升序），待定的在后（按金额降序）
  - 排除：已取消的方案、每股派息 ≤ 0、除权日已过去（那些走「分红记录」）、报告期超过 400 天的陈年未实施方案
- 月历三色标注：股权登记 · 除权除息 · 派息日，可「点击回今天」
- 年度总览：12 月柱状图（已到账 / 暂无记录 / 选中月三态）、月度到账明细（官方图标 + 代码）、**平均每月到账**（按已过去月份数平均）

### 个股详情（独立页）

- **五个时间档位**：今年 / 近2年 / 近5年 / 历史至今 / 自定义（自定义是一对起止日期）
- 主卡：**分红总额**（超大字 + 橙红）· 到账笔数 · 涉及标的 · **另有预计到账**（单列一行，绝不混进总额）· 「相当于 N 个月 ___」的趣味换算（换算对象与月费可在「我的 · 提醒与设置」里改）

- **按年**：区间跨 2 个自然年以上才出现（原「发现 · 股息统计」的年度汇总搬到这里）

### 我的
- **账户分析**：风险提醒 · 总资产与「较上次记录」· 累计浮动盈亏与浮盈比例 · **资产走势曲线**（与首页同款：持仓市值 / 净资产 / 收益率，可叠加指数、可收起；控件状态与首页各自独立） · 持仓盈亏榜 · 股息率分层 · 市场分布 · **集中度（HHI）**
- 账户管理（多账户隔离、一键切换）
- 交易流水管理（**可折叠**，成本调整记录在此展示与编辑）
- 数据管理：**跨设备同步**（可选，默认关闭）· JSON 全量导出/导入 · 交易流水 CSV · 分红台账 CSV · 清空
- **跨设备同步**：开启后手机/平板/电脑自动保持一致（前台 1 分钟内；详见下节）
- **跨设备搬运**：把核心数据编码成一段 `XJ1…` 文本或链接（gzip 压缩，**不含 OCR Key**），用微信/QQ 发到另一台设备，粘贴或打开即导入，可选**合并（自动去重）**或**覆盖**；不经过任何服务器

> **数据自愈**：应用每次启动会合并「同标的 + 同账户 + 同到账日 + 金额相符」的重复到账记录。
> 早期版本的自动登记幂等键只覆盖了自动写入的那一条，手工/OCR 补录的同一天同一笔可能被记两次。

## 跨设备同步（可选 · 默认关闭）

**它解决什么**：手机上给某只股票加仓/减仓，平板与电脑上的持仓、成本、息率、分红到账随之自动一致。

**怎么开**：「我的 · 数据管理 · 跨设备同步」→ 开启 → 粘贴一个 GitHub 令牌（**classic 令牌、只勾 `gist`、Expiration 选 No expiration**）→「检测令牌并列出我的 Gist」→ 第一台设备「新建同步位置」→ 点「**生成安装链接**」，把链接发给自己，其余设备**点开一次**就自动接入。**以后不用再登录、也不用再点链接**（详见 [多设备自动同步](#多设备自动同步怎么开开完还要不要管)）。

**怎么工作**（这一节是口径说明，不是实现细节）

| 方面 | 做法 |
|---|---|
| 同步什么 | **只同步底层事实**：交易流水、分红到账、账户、标的的用户设置（成本口径/名字/类型）、支出项、展望未来、测算带参数、偏好设置、每日资产快照。持仓、成本、息率、盈亏都是**推导值**，因此天然一致，不存在「持仓表被两边各写一次」的冲突 |
| 不同步什么 | 行情、历史 K 线、当日分时、股息率历史、分红方案缓存 —— 体积大且每台设备都能自己拉。**OCR Key 与同步令牌永不外发** |
| 中转站 | 你自己的一个 **GitHub 私有 Gist**（一个 JSON 文件 = 全量快照 + 最近的增量列表）。没有自建服务器，也不经手任何第三方服务 |
| 冲突规则 | 新增按主键并集去重（ID 天生全局唯一）；同一条被两端改过则**字段级后写胜出**，比较顺序是「修订号 → 修订时刻 → 设备号」，**第三项保证任何两台设备对同一条冲突都算出同一个结论**（设备时钟不一致也不会来回覆盖）；**删除永远获胜**（墓碑），被删的记录不会因为另一端还留着而复活 |
| 资产快照 | **按日期写一次，先到先得**，且比对时忽略本机汇率 —— 否则两台机器汇率的细微差别会让它们每天互相改写同一天的数字 |
| 触发时机 | 本地一改就推（防抖 2 秒）；前台每 60 秒拉一次（与行情刷新同节奏）；**回到前台立刻拉一次**；离开页面时尽力推一次 |
| 省流量 | 条件请求（`ETag`）：远端没变时服务端回 304，**一个字节的内容都不下载** |
| 写冲突 | `If-Match` 乐观锁：两边同时写时后者收到 412，应用会自动「拉回 → 合并 → 重试」，**两端数据都不丢** |
| 失败 | 401（令牌失效）/ 403（限流，按 GitHub 给的恢复时间退避）/ 404（Gist 被删）/ 网络不可用，**各自给出明确文案**；期间继续本地记账，联网后自动补齐。**增量在确认推送成功前不会从队列里移除**，所以中途断网也不丢 |
| `file://` | **不可用** —— 直接双击打开的本地文件没有稳定联网身份，这是浏览器限制，界面会如实说明 |

> **比功能更重要的一条**：同步关闭时，应用**不得发出任何同步请求**。这条有专门的断言守着（`uitest` 全程断网运行并校验关闭态零外发；`tools/test-syncnet.mjs` 另有 401/403/404/412/500/断网/ETag 的完整分支覆盖）。

### 核心口径

**① 预测年度分红 = 持股数 × 财年口径年均每股分红**

「近 N 年」的 N 是**完整财年个数**，不是自然日窗口：

```
最近财年 Y = 已实施方案中报告期含「年报(12-31)」的最大年份
可用财年数 M = Y − 最早报告年度 + 1
分母 = min(N, M)        N 由每只标的独立配置（默认 1）
分子 = 报告年度 ∈ [Y−分母+1, Y] 的全部已实施方案每股税前分红（含各财年中报）
```

降级链：`财年口径 → 近12个月(ttm) → 基金按12个月年化(fundTtm) → 单条(single) → 无方案(none)`

**② 成本息率 / 市值息率 / 股价息率** 均由①派生：
- 成本息率 = 预测年度分红 ÷ 总成本
- 市值息率 = 预测年度分红 ÷ 总市值
- 股价息率 = 每股年分红 ÷ 最新收盘价

| 口径 | 公式 | 说明 |
|---|---|---|
| **分红摊薄** | (净投入 − 累计已收分红) ÷ 持股数 | **默认**；分红到账后成本自动下降，允许为负 |
| 加权平均 | 买入按加权平均；卖出按均价结转已实现盈亏 | 不做分红摊薄 |
| 摊薄成本 | (累计买入 − 累计卖出) ÷ 持股数 | 允许为负，不展示已实现盈亏 |

**②b 收益率曲线（时间加权，TWR）**
```
总资产 Vₜ = 持仓市值 + 累计已收分红        （分红到手即现金，计入资产）
外部流 Fₜ = 累计净投入ₜ − 累计净投入ₜ₋₁    （加仓/减仓属外部流入流出，不是收益）
当日收益 rₜ = (Vₜ − Vₜ₋₁ − Fₜ) ÷ Vₜ₋₁
收益率指数 Iₜ = Iₜ₋₁ × (1 + rₜ)
```
与指数对比时，两边都用**同一区间起点**归一化为 0%（不同市场交易日不同，取共同的起始日）。
不用「净资产 ÷ 净投入」的原因：中途加仓会把那个比值机械拉低，与指数涨跌幅无法公平比较。

**③ 持仓成本三口径**（每只标的独立选择，**默认「分红摊薄」**）

> v4 起默认口径改为「分红摊薄」：**发生分红后持仓成本自动下降**。老数据在首次加载时一次性迁移过去（只迁移一次，之后手动改过的口径不会被覆盖）。
> 任何新建标的（手动添加、截图导入、交易录入、行情合并）都会由 `model.symbolRecord()` 统一带上口径；即使记录里没有 `costMethod`，计算层也按「分红摊薄」兜底 —— 这条是 2026-09-11 修的实缺陷，之前有 8 处创建代码漏写口径，导致那些标的落到「加权平均」上、分红不摊薄成本。
> 分红在**交易明细里以只读行**呈现（标「分红摊薄」，带每股与金额），这样成本是怎么降下来的可以直接看到；金额与日期都来自 `received` 记录，不参与二次计算，因此不会重复计数。

**③b 修改「持仓数量 / 当前成本」怎么落地**
持仓永远由交易流水推导，不另存持仓表，所以这两项**不直接写数字**，而是各自换算成一笔记录追加到流水里：

| 改动 | 落成的记录 | 说明 |
|---|---|---|
| 持仓数量 | 一笔买入 / 卖出（日期 = 今天） | 可选补记价格：**以当前成本价**（每股成本不变，默认）· **0 元**（送股 / 转增，总成本不变）· 手动输入 |
| 当前成本 | 一笔「**成本调整**」记录（signed 金额） | 只增减成本基础，**不改股数**；已清仓（股数为 0）时记录会被忽略 |

两者都会出现在交易明细里，可随时点开编辑或删除。已实现盈亏由卖出价格与卖出时点的加权成本共同决定，因此保持只读。

**④ 分红回本进度**
```
净投入 = 累计买入 − 累计卖出 + 成本调整（卖出回款也算收回本金）
剩余待回收 = max(0, 净投入 − 已收分红)
预计回本年 = 剩余待回收 ÷ 当前年分红
```

**⑤ 其他**
- 预计到账 / 预测分红一律使用**税前**金额
- 派息日：基金与港股为数据源给出的**真实发放日**；A 股口径为「派息日 = 除权除息日」（数据源无独立派息日字段）
- 年度月均到账 = 年度已到账 ÷ **已过去月份数**（历史年度 ÷ 12）
- **多币种（A股 / 港股 / 美股混合持有）**：
  - **金额一律折人民币**，来源是 `holdings()` 上成对的字段 —— `marketValue` / `costValue` / `unrealized` / `realized` / `netInvested` / `receivedTotal` / `predictedDividend` 是**原币**（内部折算与分红摊薄要用），对应的 `*Cny` 是**人民币**。**凡是带 ¥ 的显示与汇总一律用 `*Cny`**；`summary()` / `analytics()` / 持仓卡片 / 个股页 / 账户分析 / 弹层都已切过去
  - **「每股」数字（`price` / `avgCost` / `perShareAmount`）保留原币**，并在弹层里配币种符号
  - 汇率来源 `calc.cnyRateOf(state, symbol)` —— 视图层不许自己取汇率；缺 `settings.fx` 时按 1
  - ⚠️ **只做了「用当日汇率折算」，没有汇率损益**（成本与市值同用一个汇率，汇率项相减时被约掉）。详见「已知局限」第 10 条
  - ★ **一致性铁律**：`summary().totalMarketValue` 必须**逐位等于**资产走势曲线当日的 `mv`。两者分别实现过一段，口径一分叉就会「同屏两个总市值」（实测差过上万元），所以 `verify.mjs`【32】【33】两组专门锁这条
- **每日资产快照**：每次同步后记录一条（人民币口径），支撑首页账户分析页深色卡的「较上次记录」（账户分析里的资产走势曲线不依赖快照，直接由历史行情重建）
- **持仓总市值 / 净资产曲线**（首页「资产走势」卡，可一键切换、可整卡收起）：日期全集取各标的日线的并集，每只标的按「该日持股数（由交易流水还原）× 该日或之前最近一个交易日的真实收盘价（不复权；场外基金用单位净值）× 当日汇率」求和；**同日若有每日快照则以快照为准**（快照用的是当日实时行情与真实汇率）。缺历史行情的标的（多为长期停牌或未取到净值）不计入，界面如实说明
  - 净资产 = 持仓总市值 + 累计已收分红（按除权日累计）− 累计净投入；切换后图例与配色同步（净资产固定蓝色），口径说明也随之切换
- **当日分时**（首页「资产走势」卡切到「当日」时，三种指标都可画）：**收盘后照样展示**，显示的是「最近一个交易日」的走势。分时缓存**落盘持久化**（`state.minuteCache`），腾讯分时接口收盘后仍返回当天完整数据（实测 18:44 取到 267 个点、末点 15:30），所以晚上 / 周末打开也能看到曲线；每只标的只保留最近 1 天，且每个点只存 `{时刻, 价格}`（不含成交量，体积约减半）
  - 组合曲线：取各标的**分时时间戳的并集**，逐时刻求 `Σ(当日持股数 × 该时刻价格 × 汇率)`。某只标的缺某个时刻的报价时**沿用其前值**（前向填充），因此不会因某只少一个报价点就整段塌陷
  - 收益率 = 相对**当日首个报价**的涨跌幅（首个报价基准必须 > 0，否则该曲线不画）；指数分时按同一基准归一化，可横向比较
  - 持仓市值 / 净资产 = **绝对金额**（元）。净资产 = 分时持仓总市值 + 累计已收分红 − 累计净投入，其中后两项在盘中是常量
  - **★ 当日净资产必须与「全部 / 本月」等日粒度口径逐位一致**（同一个组合不该有两条净资产曲线）。它们由 `calc.netWorthAdjust` 统一提供常量项，**两个容易写错的点**：
    - **没有分时的标的（场外基金 / 美股 / 长期停牌）要把它的市值补回来** —— 它进不了逐分钟的 mv，但净投入会被扣，只扣不加会让净资产凭空少掉「市值」这一整块（实测一个含 5 万元场外基金的组合，当日净资产比真实值少了 4 万）
    - **净投入与分红都要按标的币种乘汇率** —— 日粒度用的是 `pos.netInvested × rate`，漏乘的话持有港股 / 美股的组合会按外币原值去扣成本
  - 没有分时的标的（场外基金 / 美股 / 长期停牌）**不参与逐分钟曲线**（按其最新市值作为常量计入净资产），卡片下方说明行会给出只数
  - **陈旧数据闸门**：缓存批次日期（`minuteCache.at`）必须与标的自身日期一致，且不晚于今天 —— 防止脏数据 / 混批把某天走势画到另一天上。数据不属于今天时，持仓卡片会在价格下方挂一枚 `MM-DD` 小字角标，明确告诉用户这条线不是实时
- **持仓卡片分时图限宽**：sparkline 的 SVG 用 `preserveAspectRatio="none"`（只横向拉伸），故用 `flex:1 1 auto` + `max-width:380px` 封顶。手机单列（可用 217~323px）够不着上限、自然铺满；单列宽卡（576 / 668px）与桌面两列（490 / 528px）被压到 3.8× 拉伸。**实测 9 视口横向拉伸倍率 2.17×–3.8×，全部无水平溢出**（`node tools/measure-spark.mjs`）
- **代码展示**：全站统一为「市场缩写大写 + 代码」（`SH600036` / `HK00700` / `US AAPL` / `OF110022`），不再单独挂「沪/深」标签，也不再写「· 股票」
- **技术信号标记**（持仓卡片与个股详情页）
  - 表达方式是**中性指标描述**，不是操作建议：日线满足 → 绿色 **「日线下轨」**；周线满足 → 红色 **「周线下轨」**。**两个同时满足时只显示周线**（红）。代码、注释、文案中一律不出现「买入 / 卖出 / 推荐」等字样 —— 应用红线是「只做记录，不荐股」
  - 判定条件（两条**同时**成立才亮）：① 现价 **≤** 当期布林带下轨（**含等于**）；② 当期 KDJ 的 **J < 0**
  - 指标参数为业内标准值：**BOLL(20, 2)**（中轨 = 20 日均价，上下轨 = 中轨 ± 2×标准差，**总体口径 ÷N**）、**KDJ(9, 3, 3)**（`RSV = (C−LLV)/(HHV−LLV)×100`，`K = 2/3·前一K + 1/3·RSV`，`D = 2/3·前一D + 1/3·K`，`J = 3K − 2D`，K/D 初值 50）
  - **J 可越界**（>100 或 <0）是 KDJ 的固有性质，代码中**不做 clamp** —— 判定条件正是 `J < 0`
  - **「实时」的含义**：K 线取本地缓存的历史（腾讯 `fqkline` 接口原生日线 / 周线），**当前这根优先采用接口给出的实时根** —— 实测该接口在盘中就把「今日 / 本周」那根一并返回，其 O/H/L/C 与行情接口**逐位一致**（2026-09-16 用招商银行、五粮液、腾讯控股、红利ETF 四只标的交叉验证：日K 末根 高 41.41 / 低 40.52 == 行情 今高 41.41 / 今低 40.52）。因此日线那根直接用**真实的盘中最高 / 最低**，周线那根直接用**接口原生的本周 K**（其口径与行情软件一致）。**收盘价一律校正为当下现价**，与判定所用的价格同源。**信号每次渲染都重算、绝不缓存结果**，因此现价一跳，信号可能立刻亮起或立刻消失
  - **为什么不能一律「开=高=低=收=现价」**：那样会让今日根的 `高 − 低 = 0`，把布林带的标准差系统性压低（招商银行日振幅 1.07% 被抹成 0）→ 下轨偏高 → 信号偏晚。实测在红利ETF 上，旧口径把今日根低点写成现价 3.362（等于收盘），使 KDJ 窗口内 `LLV` 抬高、`RSV` 归零 → **J = −9.47 误报信号**；采用真实高低点后 `RSV = 11.95`、**J = −0.18，正确地不亮**
  - **兜底路径**：若某日接口未返回「今日 / 本周」那根（典型是**周一早盘**，本周周K 尚未生成），则退化为「开=高=低=收=现价」（周线退化为由本周已发生的日K 聚合：开 = 本周首个交易日开盘，高/低 = 本周日K 高低与现价的极值，收 = 现价）。这条兜底保证**每周一上午的周线信号不会整段消失**
  - **数据不足时不亮**：日K 少于 20 根（BOLL 窗口）时不出信号；缓存取 **60 根**日K（`SIG_MIN_BARS` 之上留足余量），让 KDJ 的 K/D 从初值 50 充分收敛，与行情软件对得上
  - **一字板保护**：N 日最高 == 最低时分母为 0，RSV 取中性 50 —— 否则 RSV=NaN → J=NaN → `NaN < 0` 恒为 false，**信号会静默地永不亮起**，这是最难排查的一类失效
  - **场外基金不参与**（无盘中行情，直接跳过）
  - 缓存落在 `klineCache`（`symbol → { at, day[], week[] }`），与 `priceHistory`（只有收盘价、供资产走势画曲线）**分开存放**：两套刷新策略不同（K 线按天，净值曲线按需）。每只标的每天最多尝试取一次（失败也记账，避免反复重试拖慢同步）
  - ⚠️ **信号基于本地缓存的历史 K 线 + 实时现价计算，指标参数为标准值，仅供记录与参考，不构成任何投资建议。**

- **股息率曲线（财年口径）**（个股详情页，紧跟「当前市值」）
  - **定义**：某时点的股息率 = **该财年派现总额 ÷ 当时总市值 × 100%**
  - **实现上等价于「该财年每股派现合计 ÷ 当时股价」** —— 因为 `派现总额 ÷ 总市值 = (每股派现 × 总股本) ÷ (股价 × 总股本)`，总股本在分子分母中约掉。这也正是东财 `DIVIDENT_RATIO` 字段的口径（实测长江电力 FY2025：0.79 ÷ 28.24 ≈ 2.797%，接口给的值为 `0.027974504249`，吻合）。历史时点的总股本本就无从获得（数据源只在每条分红方案上带一个 `TOTAL_SHARES`），走每股口径是唯一可行的做法
  - **分子**：该财年**全部**方案的每股税前派现合计（**含中报等中期分配**）
  - **生效时点**：取该财年**年报方案的预案公告日**（`PLAN_NOTICE_DATE`，缺失时依次退回 公告日 → 股权登记日 → 除权除息日；四者全缺则整个财年不参与）。即长江电力 FY2025 年报预案 2026-04-30 公告，曲线在这一天就从 FY2024 的分子切到 FY2025 的分子
  - **含预案**：**不过滤 `isImplemented`** —— 已公告但尚未实施的方案也计入。这是「公告日生效」的必然要求：若只算已实施，切换点会实际滑到 2~3 个月后的除权除息日，「公告日生效」就形同虚设
  - **只认含年报的财年**：光有中报不足以为一个财年定调（与 `annualBasePerShare` 的严格度一致）；该财年派现为 0 的也不参与
  - **时间轴粒度：一律交易日（日线）**，默认**最近十年**。取数分**两个窗口**拼接：腾讯 `fqkline` 单次 `count` 的硬上限是 **2000 根**（实测 `2000` 正常、`2050` 起直接空返回），而 2000 根日线只有约 8.2 年；但它的 **`beg`/`end` 参数是生效的**（实测 `code,day,2015-06-01,2015-12-31,640,` 精确返回该区间的 146 根），所以拆成「近 8 年」+「再往前 3 年」两次请求再拼接 —— 实测合计 2601 根、跨 3907 天、**无重复无缝隙**（边界日可能同时落在两个窗口里，按日期去重）
  - **为什么不退回周线**：早先的版本为了凑满十年用了「远端周线 + 近端日线」的双粒度，结果曲线相邻点差好几天、看起来根本不像日线。分窗拼接虽然多一次请求，但换来了**任何缩放层级都是交易日粒度**
  - **除权除息日散点**：取自各方案的 `exDividendDate`。散点会**吸附到曲线上最近的一个已有数据点**（超过 7 天则丢弃，避免把十年外的日期吸到最左端画出假点），**晚于曲线最后一天的（未来才除权）直接不画** —— 否则会被吸到最右端，等于把「还没发生」画成「已经发生」。**刻意不把散点日期并入横轴**，否则既毁掉吸附、又会让横轴出现非均匀的时间步长
  - **`yieldHistory` 与 `klineCache` 分开存**：那套是完整 OHLC、只留 120 根、给 BOLL/KDJ 用；这套**只存收盘价、最近十年日线**（约 2600 点/标的）。缓存带 `v: 2` 标记，旧的「日线+周线」双粒度缓存会被丢弃重取，避免粒度忽粗忽细
  - **拖动读数不会出现「—」**：横轴是各曲线日期的**并集**（余额宝基准是周频，交易日与它天然错开），某条曲线在别人的日期上必然有点是空的。`renderCompare` 会对每条曲线做**前值填充**（开头没有更早值的用首个已知值回填），因此任何一天都能读出数值 —— 曲线本来就是等距连线的，读数与画出来的线一致
  - **除权除息日散点**：取自各方案的 `exDividendDate`。周线视图下这些日期多半不是周五，所以散点会**吸附到曲线上最近的一个已有数据点**（超过 7 天则丢弃，避免把十年外的日期吸到最左端画出假点）；**刻意不把散点日期并入横轴**，否则既毁掉吸附、又会让横轴出现非均匀的时间步长
  - **底部时间轴（brush）**：独立成**第二个 `<svg data-brush="…">`**（不是画进主图），因为拖动时要实时重画主图 —— 若抓手与主图同在一个 SVG，重画会把抓手自身删掉、正在进行的 pointer capture 随之中断。拖动中只改抓手/蒙版并重画主图容器的 `innerHTML`，**全程不碰 store**；范围**每次变化都静默写进 `ui.yjBeg/yjEnd`**（不走 `setUI`，否则整页重建会导致滚动跳动）—— 拖动中也记，是为了「万一中途被后台重渲染打断」时能接着拖
  - **拖动中途被重渲染打断的处理**：离线时失败的行情/分红请求会走到 `.catch` 里的 `notify()`，可能就是一次整页重建，此刻正被拖的 SVG 会脱离文档。`chart.js` 会**按 `chartKey` 把那个 SVG 找回来、并从 `ui` 里取回选区继续拖**，而不是让手势静默中断（早先的写法是直接放弃这次拖动）
  - **余额宝七日年化对比线**：**默认关闭**，点图例即可开关（状态持久化在 `settings.showYieldBench`，跨会话保留）。数据来自天天基金 `pingzhongdata/000198.js` 的 `Data_sevenDaysYearIncome`（实测 4856 个点、2013-05 起），与场外基金净值走**同一条 `<script>` 注入通道**（该域没有 CORS 头，只能靠注入执行 JS 变量再读 `window.*`）；解析时**按周取每周最后一个点**并裁到最近 10 年 —— 七日年化极平滑，日频纯属浪费存储与渲染。**仅在用户打开该曲线时才发起请求**
  - **场外基金与美股不画**：场外基金分红不定期、没有「财年派现」这个概念；美股无分红数据源。这两类只显示一行说明（判定统一走 `market.supportsYieldCurve`，与取数层的过滤条件保持一致，避免出现「界面说能画、数据却永远取不到」的空态）
  - **历史平均股息率线（分财年，冷色虚线）**：**常亮显示、不可关闭**；点图例里那一项是**切换口径**（不是开关）：
    - **整年均值**（默认）：取该财年**整段生效窗口内**股息的逐日平均 → 每个财年是一条水平线，连起来就是阶梯。窗口内**样本不足 120 个交易日**（≈半年）的财年段**整段不画**，所以新财年通常要在生效后约 4~6 个月才会出现
    - **自切换日起累积**：只用**生效日到当天**的样本逐日累积平均 → 是一条爬升的曲线，**无前视偏差**（读者能看到「当时能看到的均值」），因此**刻意不设样本门槛** —— 样本少正是它要如实反映的事实
    - **样本一律从 2022-01-01 起算**，且**与底部时间轴选区无关**：均值是「该财年」的属性，不该随缩放而变
    - **为什么必须分财年，而不是全期一个均值**：一个财年窗口内分子（每股派现合计）是常数，所以「该财年的平均股息率」完全由价格决定 —— 只有这样才能把「高于 / 低于均线」读成**价格位置的相对高低**。若改用**全期单一均值**，均线的高/低于会被**分子档位**锁死：实测中远海控自 2022-01-01 起 1142 个交易日里，只有 FY2022 那 241 天「高于均值」、其余 901 天恒为「低于」，穿越次数仅 **2** 次，信号等于失效（同一标的下分财年口径是 **54** 次）
    - **文案保持中性**：界面只出现「高于均值 / 低于均值」，**不出现「买入 / 卖出」**（与全项目的产品红线一致）
    - **零新增请求**：完全由本页已有的十年日线缓存 + 分红方案在纯函数里算出（`calc.yieldYearAverages` / `calc.yieldAverageSeries`），不引入任何新数据源
  - ⚠️ **已知偏差**：① 用**不复权**收盘价（与项目「历史市值必须用真实价」的口径一致），若标的在该财年内做过送股/转增，除权日前后会出现一次台阶 —— 除权除息日散点正好标出这些位置；② 曲线**含预案**，而页面上的「股价息率」卡片只算已实施，因此两者在「年报已公告、尚未除权」的那段时间里会不一致（曲线偏高），这是有意为之；③ 股本发生变动的年份存在二阶偏差。

### 派息日弹窗（今日分红到账）

- **触发**：当天有派息事件 —— 与「分红日历」**完全同源**（都走 `calc.calendarEvents` 的 `payout` 事件），所以弹窗里的金额 / 名称 / 笔数跟日历上看到的一定一致，不会两处打架
- **频次**：**每天最多一次**。标记 `settings.payoutPopupAt` 记的是「最近一次弹过的日期」，存在 settings 而不是内存 —— 跨会话、甚至跨设备导入后都不会重复弹
- **时机**：挂在 boot 的两个时点上各判断一次（首次渲染后 600ms + 同步完成后）。**刻意不放在 render 里** —— 分红方案是异步拉的，太早判断会「今天明明有派息却弹不出来」。判断本身幂等；**当天没有派息时既不弹也不写标记**，否则方案还没到手就白白错过一整天
- **金额口径**：股权登记日当天的持股数 × 每股税前派现（与日历一致）
- **只对「派息日」弹**：股权登记日、除权除息日都不触发
- ⚠️ **文案如实说明**：A 股的派息日 = 除权除息日，是**推算值**（`isEstimate`）。弹窗照样写「今日分红到账」，但**只在确实是推算值时才附一行小字**「A 股派息日按除权除息日推算，实际到账可能晚 1-2 天」—— 否则用户发现钱没到会以为是 bug

### 分红汇总（独立页）

口径全部来自 `calc.dividendSummary(state, accountId, range)` 这一个纯函数（`tools/test-divsum.mjs` 有 233 项断言独立复算）。

- **时间档位 → 区间**（`calc.dividendRange`）：

  | 档位 | 区间 |
  |---|---|
  | 今年 | 本年 01-01 ~ 12-31 |
  | 近2年 / 近5年 | 往前 1 / 4 年的 01-01 ~ 本年 12-31 |
  | 历史至今 | **该账户**最早一条到账记录 ~ **今天** |
  | 自定义 | 用户选的起止（end 早于 beg 时夹到 beg，不会产出负区间） |

  上界「取年末」是有意的：这样**今年**档的「另有预计到账」才能把本年剩余还没发的分红算进来。而「历史至今」语义上不含未来，它的 end 就是今天 —— 于是那一档的预计**恒为 0**。
- ★ **两种口径严格分开**，这是这个页面最重要的一条：
  - `total` = **已到账**（受「今天」约束，只可能 ≤ 今天），主数字用它，保证与「我的 · 分红流水」**逐笔对得上**
  - `pendingTotal` = 区间内**还没到账**的预计，界面上单独一行，**绝不混进主数字**
- **金额一律税前**（全站统一口径）。「境外红利税」**刻意不做** —— 项目没有境外预扣税数据源，与其编一个不如只显示税前，已在局限里注明
- **账户维度跟随账户切换器**；币种统一折人民币（与 `*Cny` 口径一致）。注意：**全部账户**视图下，同一标的的多账户持仓会合并成一条预计事件（与日历同行为）
- **趣味换算**：`calc.funEquivalent(total, monthly)` = `floor(total / monthly)`；换算对象与月费存 `settings.dividendFun`（默认「视频会员 ¥25/月」，可在「我的 · 提醒与设置」里改）。月费为 0 或分红为 0 时返回 `null`，界面直接隐藏那一行
- **零新增数据源**：全部由已有的 `state.received` + `plans` 在纯函数里算出，不发任何新请求
- **原「发现 · 股息统计」区块已移除**：内容整体搬进本页（年度汇总 → 「按年」区块，按标的 → 「按标的」列表），发现页只留入口卡

### 资产走势（首页 / 账户分析）

- **三条曲线**：持仓市值 / 累计收益 / 收益率。区间：当日 / 本月 / 近三月 / 近6月 / 今年 / 全部 / 自定义。
- **「累计收益」不是「总资产」**：`= 持仓总市值 + 累计已收分红 − 累计净投入`。**本项目没有现金概念**，所以不提供券商那种「总资产（持仓 + 可用现金）」曲线 —— 这也是它与券商 App 曲线数值对不上的根本原因（同一个组合，市值 130 万，累计收益只有 25 万）。
- **当日收益率 = 相对【昨收】的涨跌幅**（与同花顺/券商同口径）：
  - 分母 `base = Σ 持股数 × 昨收 × 汇率`，取的是**全组合**的昨收市值；
  - **尚未开盘的标的在分子里贡献 0、在分母里照常占权重**。A 股 09:30 开盘、美股北京时间 21:30 开盘，早先拿「首个时刻的 mv」当分母时，那一刻只有 A 股在报价 → 分母偏小 → 涨幅被放大好几倍（这就是「当日收益率偏高」的成因）。
  - 昨收缺失时的兜底链：行情给的 `prevClose` → 该标的日线最后一根收盘 → 现价。三者都没有则该标的既不进分子也不进分母（**绝不拿 0 当昨收**）。
  - 对比指数同样按昨收归一化（取 `indexHistory` 里分时批次日之前的最后一根收盘），与组合同口径。
- **当日参考盈亏**（首页深色卡 / 持仓卡片 / 资产走势卡）`= Σ 持股数 ×（现价 − 昨收）× 汇率`，人民币口径、跨币种已折算，**不含当日已到账分红**。
- **收益率两种口径可切**（图例下方的胶囊）：
  - **时间加权（TWR）**：按日剔除加仓/减仓的净流入后连乘，可与指数公平对比；
  - **成本收益率** = 累计收益 ÷ 累计净投入，即「每一元本金赚了多少」。净投入 ≤ 0（本金已被收回）时该点返回 `null`，**不给 Infinity**。该口径**刻意不叠加指数** —— 指数没有本金概念，两者零点不同，叠在一起比会被误读。
- **历史深度约 10 年**：腾讯 `fqkline` 单次 `count` 上限 2000 根（≈8.2 年），但 `beg`/`end` 生效，所以按 `[今天−8年, 今天]` + `[今天−11年, 今天−8年]` **两窗拼接**拿满（实测 2601 根 / 10.7 年、无重复无缝隙）。**只在首次或老缓存升级时深取一次**（`priceHistory[sym].deep === 2` 作为标记），之后每天只增量拉最近 800 天再与旧点按日期合并。
- **两条铁律**（`verify.mjs`【32】【33】锁着）：`summary().totalMarketValue` 必须逐位等于曲线当日 `mv`；「当日累计收益」必须逐位等于日粒度今日 `nw`。后者要求两侧**用同一个标的集合**（都只算「有日线」的标的），否则「无日线但有分红」的标的会让两条曲线打架。

## 已知局限

1. **A 股派息日口径** —— A 股数据源没有独立的「派息日」字段，口径上「派息日 = 除权除息日」，界面标注为「预计派息日」；**基金与港股是数据源给出的真实派息日**。请以券商实际到账为准。
2. **美股不支持自动同步分红** —— 无公开可用的免费分红数据源，美股持仓只提供行情、成本与盈亏；分红可在个股页「分红记录 · + 添加」中手工补录，补录后股价息率与回本进度照常计算。
3. **美股当日分时不稳定** —— 腾讯分时接口对美股只回 1 个点，改用东财 `trends2` 时该接口时好时坏；取不到就不画走势，只显示现价与涨跌幅。此时该持仓卡片仍正常显示行情与四列数据，只是没有卡内 sparkline；首页曲线也会把它计入「没有当日分时」的只数。
4. **场外基金没有分时** —— 无行情接口；历史市值曲线用天天基金的单位净值走势代替收盘价。受此影响，场外基金在「当日」区间下既不出现在首页组合曲线里，卡片上也不画 sparkline。
5. **日经225 / 台湾加权 / 韩国KOSPI 无历史数据源** —— 实测腾讯、东财、同花顺、新浪、网易五家都没有浏览器可达的免费历史（详见「对比指数清单与可用性」）。界面**整项不显示这三个指数**（此前是置灰标注「无数据」，现改为直接不列出），不做假数据。
6. **美股指数没有分时** —— 只有 A股/港股指数能画「当日」分时；美股指数在「当日」区间下置灰。
7. **部分标的拿不到官方图标** —— ETF 与场外基金在同花顺 F10 与东财公司资料表中都没有公司标识通道，此时统一回退到**两字中文简称**头像（如「易方」）。若某公司的标识本身就是纯灰度图，会被验真规则判为占位图而回退文字头像。
8. **图标解析依赖第三方** —— `icon.horse` / `api.xinac.net` / 同花顺 F10 任一改版或限流都会让对应通道失效；此时回退文字头像，不影响其它功能。
9. **分红个税未计入** —— 统一使用税前口径。实际个税与持股期限挂钩（不足 1 个月 20%、1 个月至 1 年 10%、超过 1 年免征）。
10. **多币种以人民币折算为主口径，但「汇率损益」不计入** —— 这条要说清楚，尤其是**港股通**（人民币 → 港币 → 港股，而港币又与美元挂钩，于是人民币兑美元的波动会额外带来一层损益）：
    - **金额（市值 / 成本 / 盈亏 / 净投入 / 分红）一律折成人民币**：首页 hero、顶部副标题、账户分析、展望未来、持仓卡片「市值」列、个股页各金额、分红记录金额，用的都是折算后的值；**同时持有 A股 / 港股 / 美股时不会再把外币金额当人民币相加**（曾经会，同屏能差出上万）
    - **明细里的「每股」数字保留原币**（每股成本、现价、每股分红）—— 港股的价格本来就是港元，折了反而和行情软件对不上；弹层里这类金额都带币种符号（`HK$` / `$` / `¥`）
    - ⚠️ **成本与市值用的是同一个「今天」的汇率，所以汇率本身的损益被约掉了**。举例：买入 100 股 @300 HKD，当时 1 HKD = 0.95（实付 ¥28,500）；现价仍 300 HKD，今天 1 HKD = 0.92（现值 ¥27,600）——**真实盈亏是 −900 元、全是汇率**，而本应用会显示「未实现 0」。已实现盈亏（卖出）同样是**纯原币**口径，卖出结算回人民币时的汇率损益也不体现
    - **原因**：`settings.fx` 只存了**一个最新汇率快照**，没有历史汇率序列，拿不到「买入日汇率 / 卖出日汇率」。（技术上可行——实测腾讯 `whHKDCNY` / `whUSDCNY` 的日线历史与股价同一个端点、字段序一致、分窗取长历史同样可行——只是尚未实现。）
    - **汇率缺失时按 1 折算**；历史曲线与快照同样只用当日汇率，未做汇率历史回溯
11. **净资产曲线不含现金与负债** —— 本应用没有现金与融资账户概念；分红再投（用手工买入记录）会被重复计入一次。
12. **多设备默认不自动同步** —— 每台设备的数据独立存在本地，同步**默认关闭**。开启「我的 · 数据管理 · **跨设备同步**」后，手机/平板/电脑会在**前台 1 分钟内**自动保持一致；不开启则可用「我的 · **跨设备搬运**」生成一段文本/链接（或走 JSON 导出导入）。这是隐私优先设计下的自觉取舍：**同步是可选项，默认不参与**。
13. **开启同步后，数据会离开本机** —— 持仓、交易、分红到账、支出项与偏好设置会被**明文**存进**你自己的一个 GitHub 私有（secret）Gist**，作为三端中转。因此：① 只有填了同一个令牌的设备能读它，但 Gist 不是加密存储，**别把它的链接公开分享**；② 令牌只存在各设备本地，**不进同步内容、不进任何导出文件**；③ 关闭同步后应用**不会再发出任何请求**；④ **绝对不要把该 Gist 改成公开** —— GitHub 检测到令牌被推到公开位置会**自动吊销它**，三端会一起断开（应用检测到公开 Gist 时会停止同步并提示）；⑤ 本机「清空本地数据」**只清本机**，云端与其他设备不受影响。
14. **同步能承诺的上限是「前台实时」** —— 移动端浏览器在锁屏/切到后台时会被系统挂起，**无法**做后台推送。因此能保证的是：对方正打开着时前台 1 分钟内刷新，以及**一回到前台立刻对齐**。同步失败会**如实显示原因**（令牌失效 / Gist 被删 / 限流 / 断网），连续失败会在入口上挂警示，**不会静默失败**。已实现：插入幂等、字段级后写胜出（设备时钟不一致也能收敛）、删除墓碑防复活、资产快照按日期写一次。
15. **`file://` 下能力受限** —— 不能注册 Service Worker、无系统级推送、**也无法使用跨设备同步**（浏览器不给 `file://` 页面稳定的联网身份），离线时仅能读取上次缓存的数据快照。
16. **交易日未做判断** —— 日历按自然日展示，不区分交易日与节假日。
17. **公开接口的稳定性风险** —— 可能因对方改版或限流暂时不可用；此时应用会提示「行情未能刷新，当前展示缓存数据」，不影响已有记录。
18. **历史行情首次较慢** —— 首页资产走势曲线需要每只标的各拉一次历史日线（约 1–3 秒/只），首次打开会在后台完成，期间曲线显示「正在获取历史行情」；结果按天缓存并随 JSON 一起导出。图标解析同理（同花顺单页约 300KB），也在后台跑。
19. **截图识别会上传截图到智谱 AI** —— 识别由智谱 GLM-4V 完成，截图会上传到 `open.bigmodel.cn`（首次使用有明确告知并需确认）。本应用没有后端，不经过任何中间服务器。介意上传请用「手动添加」。默认使用免费档 `GLM-4V-Flash`。**单文件版**内置 Key、开箱即用；**部署版（`dist/pwa/`）的 Key 已置空**，首次使用需到「我的 · 截图识别设置」填一次自己的 Key（[免费申请](https://open.bigmodel.cn)）。导出的备份 JSON 与跨设备搬运内容均**不含 Key、也不含同步令牌**。
20. **技术信号是参考，不是建议** —— 指标基于本地缓存的**历史 K 线（不复权）+ 实时现价**计算，参数取业内标准值；信号仅在满足条件时亮起，**不构成任何投资建议**，也不代表事后一定会发生什么。另有三个已知局限：① 首次打开时 K 线缓存为空（需一次后台拉取才可能出信号）；② 日线那根的**高 / 低点用接口给出的实时值**（已实测与行情接口逐位一致），但在**极早盘**接口尚未返回今日根时会退化为「开=高=低=收=现价」，此时波动率被低估、下轨位置与收盘后的最终值会有细微差异；③ 若某标的既没有免费日线源（如部分美股）或当天拉取失败，则该标的不会出信号。
21. **当日分时是「最近一个交易日」的快照，不是实时推送** —— 分时缓存落盘保存、每只标的只留最近 1 天，因此晚上 / 周末 / 长假打开时看到的是**上一个有数据的交易日**的走势（持仓卡片上会挂一枚 `MM-DD` 角标提示）。数据本身来自腾讯分时接口的当日完整序列（收盘后仍可取到），但若当天完全没有同步过行情、或接口当天拉取失败且本地无缓存，则该标的没有可分时曲线。缓存随时间会过期（隔天刷新即覆盖），这也是为什么它不进导出备份。
22. **股息率曲线的三个已知偏差** —— ① 用**不复权**收盘价（与「历史市值必须用真实价」的口径一致），若标的在该财年内做过送股/转增，除权日前后曲线会出现一次台阶，**除权除息日散点正好标出这些位置**；② 曲线**含已公告的预案**，而同一页「股价息率」卡片只算已实施，因此在「年报已公告、尚未除权」的那 2~3 个月里两者会不一致（曲线偏高），这是有意为之而非 bug；③ 股本发生变动的年份存在二阶偏差（数据源只在每条分红方案上带一个总股本，拿不到逐日的股本序列）。另外**场外基金与美股不画这条曲线**（基金分红不定期、没有「财年派现」概念；美股无分红源）；**余额宝基准线是周频**（该数据本身极平滑，画日频只是徒增体积），且默认关闭。
23. **历史平均股息率线（分财年）的四个已知局限** —— ① **分子换档会让均线跳一格**：财年切换日（年报预案公告日）分母没动、分子整档换掉，均线随之平移，**切换日附近的读数仅供参考**；② **「整年均值」口径有前视偏差**：它用到了本财年后面才发生的价格，回看历史信号时会显得比当时「看得更准」，想避免就切到「自切换日起累积」；③ **新财年样本不足 120 个交易日时该财年段不绘制**（默认口径下），所以图上最新一段没有均线是正常的，等窗口够了会自动出现；④ 均线只是**同一财年内价格位置的参照**，**不是估值结论、更不构成任何投资建议** —— 分红本身会增减（分子换档正是这件事的体现），跨财年的均线水平不可直接比较。
24. **派息日弹窗与分红汇总的四个已知局限** —— ① **弹窗里的「今日到账」是推算到的派息日**：A 股口径为「派息日 = 除权除息日」，券商实际入账常晚 1–2 天，弹窗已附小字说明，请以银行/券商流水为准；② **只按「当天有派息事件」触发**：若当天既没打开过应用、也没同步到新的分红方案（例如首次安装且离线），那一天就不会弹 —— 靠本地缓存的分红方案判断，缓存为空时无从得知；③ **汇总页的主数字只含已到账**：未到账的部分单独列在「另有预计到账」，因此它**不会**等于「按方案公告推算的全年应收」；④ **不含境外红利税**：港股/美股的实际到手会低于页面显示值（本项目统一税前口径，且没有境外预扣税数据源），另外「相当于 N 个月 ___」只是趣味换算，不代表任何收支建议。
25. **资产走势的四个已知口径差异** —— ① **没有「总资产」曲线**：本项目无现金概念，「累计收益」= 市值 + 已收分红 − 净投入，**不等于**券商 App 的总资产，两者数值本来就不同级；② **历史市值一律乘「今天」的单一汇率**（无历史汇率序列），持有港股/美股时历史时点会有系统性偏差；③ **历史市值用不复权收盘价**（这是刻意的：算历史市值必须用当时的真实价），若标的做过送股/转增而你没记成交易，历史股数会偏少、曲线整体偏低；④ **场外基金的历史价格用单位净值**，现金分红当天净值会下跌、市值随之下降（份额不变），这是真实情况而非 bug，但会让你觉得「市值掉了」。

> `tools/measure-spark.mjs` 会灌入 61 个分时点（只写 `state.minuteCache`，不再需要伪装交易时段 —— 分时图已不受时段限制）。它用的种子数据直接从 `uitest.mjs` 里抽取，不另维护一份。
>
> ⚠️ `uitest.mjs` 的页面内探针是**模板字符串**，有两个必踩的坑：① 写在里面的正则会被吞掉转义（`\s` → `s`、`\d` → `d`），表现为 `Invalid regular expression`；② **反引号会直接结束模板**。探针里要解析文本请用 `indexOf` / `slice`，不要用正则、也不要写反引号。
>
> ⚠️ **模拟拖动必须打在「当前文档里真实存在」的元素上**：探针常常是先 `querySelector` 拿到抓手再派发事件，但如果这中间发生过整页重渲染（离线时失败的请求会 `notify()`），拿到的节点已经脱离文档，**而脱离文档的节点派发事件不会冒泡到 `document`，document 级委托的处理器根本不会触发** —— 现象是「快照前后一模一样、什么都没发生」，且**时通时不过**。正确做法是用 `document.elementFromPoint(clientX, clientY)` 取该坐标下活的元素再派发。
>
> 💡 定位这类「只在 uitest 里复现」的问题时，别一轮轮跑 3 分钟的 9 视口全量。写一个单视口、无截图的小脚本（约 40 秒），把**拖动前/后的同组字段一起打出来**（抓手 transform、蒙版宽度、日期标签、主图 path 长度），一眼就能看出到底是「没触发」还是「触发了但画错」。

**架构约束**：`views → store → calc / fetcher`，严格单向。`calc.js` 全部纯函数，不碰 DOM 与存储，因此可被 `verify.mjs` 在 Node 沙箱中直接加载做**独立复算**。

**三条一致性铁律**
1. **单一真源**：持仓永远由 `transactions` 推导，不另存持仓表（所以没有「直接改数量/成本」的入口）——改数量与改成本只换算成新的交易 / 成本调整记录
2. **方案与到账分离**：`DividendPlan`（预告）与 `DividendReceived`（已发生）不得混用；自动到账幂等键 = `planId + accountId`，并有「同标的+同账户+同到账日+金额相符」的二级去重
3. **同一数字只有一个算法**：页面显示的每个数字都能在 `verify.mjs` 找到对应断言，不允许视图内联计算
